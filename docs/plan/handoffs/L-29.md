### What changed and why

The old hidden handler remembered only whether streamRef still existed. An iOS track end/mute could clear that stream first, losing the intent to restore it. The hook now records the running-camera intent before releasing a background-lost stream and keeps the disconnect error hidden while waiting to return. On visibility/pageshow, the tested pure cameraRestoreAction decides none/play/restart. Restore intent is consumed before async work; starting/restoring guards prevent duplicate requests.

Ended/muted/no-video streams receive one start() attempt, the same full path as Try again. A live stream just resumes playback (Android behavior preserved). If a live-looking stream's play fails on return, it gets that same one full restart. A failed restart leaves the existing error/manual recovery state; it does not loop on later pageshow events. Explicit stop clears the intent and cancels pending requests using the existing generation guard. Visible disconnects retain L-04's immediate Camera disconnected error. Automatic recovery preserves the current inference pause; it does not restart an abandoned countdown or take.
