### Interruption behavior

- A mute/end initially pauses inference and preserves the camera-on intent and track handlers. `CAMERA_LOSS_GRACE_MS = 1500` is explicitly **untuned**. The pure event transition recognizes both mute/end then hidden and hidden then mute/end; visibilitychange, pagehide and blur all establish an interruption. Repeated loss signals do not extend the original grace period.
- If the page stays visible and no unmute arrives, the grace deadline retains L-04's `Camera disconnected` error. A later unrelated focus/pageshow cannot revive that failed camera. An actual unmute can end a transient mute without reopening a live stream; an ended track cannot be revived by unmute.
- On visible return, a lost/muted stream gets one automatic call through the same `start()` path as Try again. A usable/unmuted stream resumes playback without reopening the camera. Intent is consumed before asynchronous work, so duplicate visibility/pageshow/focus events cannot loop retries. A failed automatic attempt surfaces its error.
- An explicitly stopped camera stays off. Release/unmount cancels the grace timer, removes mute/unmute/ended handlers, clears recovery state, and invalidates pending starts/playback. Automatic recovery preserves paused inference on result/review screens.
- A stream lost while the initial model promise is still pending does not wait forever in `video.play()` on an ended track; once preparation finishes it can take the same one return-time restart. Permission and model failures remain errors, even during blur; only interrupted playback is deferred.
- Practice changes are exactly **two small edits**: pass the preparation flag when a sign is selected outside browsing, and let the existing capture-abandonment effect show its notice for `interrupted` as well as `error`. Countdown/recording buffers stay discarded and do not resume or score on return. No hot CSS/App file changed.
