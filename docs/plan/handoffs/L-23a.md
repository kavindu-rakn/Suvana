### API for L-23's owner

Import from `src/storage/profile.ts`:

```ts
getActiveProfile(): 'default' | 'demo'
setActiveProfile(profile): boolean
resetProgress(profile = getActiveProfile()): Promise<void>
profileDatabaseName(profile): string
```

Default retains **ssl-learn** (version 3), so old progress is preserved. Demo uses **ssl-learn-demo** (version 3) with its own attempts, recordings and latency stores. Existing attempt/recording/latency callers automatically use the active profile without changing their signatures. `withStore` accepts an optional fourth explicit profile for resets; operations capture their profile before the first await, so a subsequent switch cannot redirect a pending write.

Selection uses localStorage key `suvana.learn.profile`, with guarded reads/writes. Unknown stored values default safely to default. `setActiveProfile` rejects invalid input; `false` means selected in memory for this page, but persistence was blocked. Other already-open tabs keep their current selection until reload. No cross-browser or account synchronization.

`resetProgress` clears only the requested database's attempts in a committed transaction. It does not change current selection, delete the database, remove reference recordings, erase latency measurements or touch the other profile. Derived mastery becomes new/0; future stars/goals/XP/streak must also derive from that profile's attempt history. Storage denial/transaction abort rejects; the UI must show failure, not announce a successful reset.

UI integration rules for L-23 (not implemented here):
1. Confirm a reset in the UI before calling it. Disable profile switching/reset during an active recording.
2. On switch, clear the current practice session via learner/session.ts `clearSession()` and refresh/remount the views' loaded attempt/mastery state. sessionStorage and mounted React state are outside this storage task; merely changing the database selection cannot refresh them.
3. On resetting the active profile, clear its mounted session/derived state after the reset succeeds. An inactive-profile reset must not clear the other profile's active session.
4. Show a notice when setActiveProfile returns false. Never present progress as synced to a Communicate account.

Namespace selection lives in db.ts, its existing single storage owner; profile.ts exposes that API plus reset. This avoids an import cycle or ineffective dynamic-import warning without adding dependencies or editing package/lockfiles.
