### What the test does

One sign goes through four scripted attempts (Try 30, Try 50, Try 76, unrevealed Recall 66, all on day 0) plus a check five days later with no attempt. After each step it calls the same functions the interface calls: `summarizeAll` and `practiceNeed`/`isDueReview` (mastery.ts), `starsFor` (game.ts), `nextExercise` (nextExercise.ts) and `startUnitSession` (session.ts, what "Practise this unit" calls in PathView). It prints two markdown tables and asserts them exactly, so if the rules change the test fails and the thesis tables must be re-copied. Run it with:

```bash
cd apps/learn && npx vitest run src/learner/workedExample.test.ts --silent=false
```

At the five-day check the sign is due because of staleness, but the reason shown is "review: score dropped", not "review: not practised for 5 days". The reason rules are checked in a fixed order, and the latest score (Recall 66) is below the previous one (Try 76), so the drop rule fires first, comparing a Recall score with a Try score. It matches ADAPTATION.md ("reasons are literal rules") and the thesis says so honestly.
