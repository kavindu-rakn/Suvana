# Learn: Sri Lankan Sign Language learning and practice (web app)

Interactive Sri Lankan Sign Language (SSL) learning and practice module
(R26-SE-019, Component 4). React + Vite + TypeScript, with MediaPipe Tasks
Vision running fully in the browser: no video ever leaves the learner's device.

The same source builds two deployments:

- **Standalone**, from the team repository: `learn-ssl-module.vercel.app`.
- **Suvana's Learn module**, at `https://suvana.help/learn/`. Everything
  Suvana-specific sits in `suvana.config.json` (base path `/learn/`, Suvana
  wiring on). Without that file the build is the standalone module, and
  Suvana-only code stays off (`import.meta.env.VITE_SUVANA !== '1'`).

This README describes Learn as merged on Suvana `main` on 18 Oct 2026. The
adaptation rules live beside the code in
[`src/learner/ADAPTATION.md`](src/learner/ADAPTATION.md).

## What a learner does

- **Learning path.** 53 units cover all 490 single signs (503 places; a few
  signs appear in two units). Units are generated by rules from the reference
  data and verified meanings (`scripts/curriculum-report.mjs` →
  `src/data/curriculum.ts`), and their structure was approved by kvn. A unit is
  passed when every sign has at least one star; the next unit opens when all
  earlier ones are passed. The badge says *Passed* until every sign has all
  three stars, then *Mastered*. A unit whose signs are not all available in the
  content edition being served is a preview and cannot be completed.
- **Watch, Try, Recall.** Each sign opens in *Watch*: the reference skeleton at
  0.5x for two loops, then 1x, with speeds 0.25x–1x, drawn in raw framing with
  an optional zoom to the hands (phones start zoomed). *Try* records an attempt
  with the reference available (optional ghost overlay). *Recall* unlocks at two
  stars: the cue is the verified English meaning, else the gloss label, and the
  reference stays hidden until revealed or scored.
- **Capture.** Recording starts only after the hands are tracked in 5
  consecutive frames, lasts `max(2 × reference duration, duration + 3000 ms)`,
  and the take is trimmed to its tracked span exactly as references are
  (`src/scoring/trimTake.ts`).
- **Feedback.** A 0–100 match score with one label scale (`band()`:
  85 *Great match*, 60 *Getting there*, below *Keep practising*), per-hand
  scores for two-handed signs, up to two short tips (missing hand, hand path,
  timing), and a side-by-side replay that follows the DTW alignment at half
  speed and pauses where the attempt differed most. **Some signs also show
  finger labels**: *Correct / Almost / Wrong* per finger, with no numbers, for
  the 22 signs with fitted per-sign cut-offs (see *Finger labels* below). Scores
  are matches to one signer's reference, never judgements of correctness.
- **Stars, goal, streak.** Try 60 / 70 earns one / two stars; an unrevealed
  Recall of 60 or more after the two-star Try earns the third. Daily goal: 5
  scored attempts per local day; the streak counts goal days. These thresholds
  are kvn's approved product rules (13 Oct), not calibrated values.
- **Adaptation.** Rule-based by design: due reviews first, then the next unseen
  sign in unit order; finite unit sessions mix two reviews with one new sign;
  each choice shows its reason under "Why this sign?". The result screen also
  suggests the next exercise for the sign (for example quarter speed after two
  low Tries). Full rules: [`ADAPTATION.md`](src/learner/ADAPTATION.md); a worked
  example is printed by `src/learner/workedExample.test.ts`.
- **Scenarios.** Two scripted conversations, each played *Guided* (reference
  shown first) or *Recall* (sign shown after the turn): *Restaurant* (5 turns,
  complete) and *Social Gathering (Introductions)*, a preview with 3 of 7 turns
  playable.
- **Experimental sentence challenge.** After the last unit: 19 whole-sentence
  clips from the Kaggle corpus, cued by their dataset labels exactly as written,
  matched as one whole sequence, no stars, always labelled *"Experimental:
  whole-sentence match, not calibrated"*.
- **Free practice and links.** Any sign can be practised at any time.
  `/learn/?sign=NAME` (standalone: `/?sign=NAME`) opens Practice on that exact
  single-sign gloss in Watch; anything else starts normally.
- **Content edition.** The default build serves the full corpus as a free,
  non-commercial academic edition (DN-04 (a)): every screen's footer shows
  *"Full corpus for non-commercial academic use. No payments. No ads."* with
  credits for both corpora. `VITE_CONTENT=cc0` makes only CC0 references
  selectable; it is a preview, not a cleared commercial edition, and it shows
  no finger labels (the cut-offs were fitted to Yohan references). Licences:
  [`public/references/LICENSES.md`](public/references/LICENSES.md).
- **Video.** None. Corpus video is not shown (DN-05); references are landmark
  skeletons only.
- **Account and profiles.** In the Suvana build the nav bar shows the shared
  Suvana sign-in (homepage `/login`, `/register`). Practice never requires it,
  and progress stays in this browser's IndexedDB; it does not follow the
  account. *My progress* and *Demo progress* are separate profiles, and a reset
  clears only the chosen one.

## Run it

```bash
npm install   # also copies the MediaPipe WASM runtime into public/wasm (postinstall)
npm run dev   # Suvana: port from suvana.config.json (5174); standalone: 5173
```

Agent lanes pass their own port (`npm run dev -- --port 5204`). The camera
needs `localhost` or HTTPS. `npm run build` produces a static build
(`dist/learn` in Suvana, `dist` standalone).

## How it fits together

- `src/vision/` — the MediaPipe `HandLandmarker` (VIDEO mode, 2 hands, GPU with
  CPU fallback), served from our own origin (`public/wasm`, `public/models`);
  the webcam hook, overlay drawing and the camera lifecycle (released when not
  needed, one automatic restart after a background or iOS interruption,
  "Camera disconnected" when it cannot recover).
- `src/scoring/` — normalisation and features, DTW, `scoreAttempt`, the
  two-hand rule, take trimming, tips (`hints.ts`), finger deviation and the
  generated per-sign finger cut-offs (`fingerCutoffs.ts`), and `band()`.
- `src/learner/` — the attempt log, mastery and practice need, sessions, game
  rules (`game.ts`), the next exercise (`nextExercise.ts`), activity, and
  `ADAPTATION.md`.
- `src/data/` — the curriculum, verified meanings (`translations.ts`, kvn
  verified; never add one yourself), sentence clips, categories and scenarios.
- `src/storage/` — reference loading, the bundled reference index, IndexedDB
  stores, profiles and storage that fails safely.
- `src/metrics/` — end-to-end feedback-latency measurement.
- `src/components/` — Hero, Path, Practice (with Watch/Try/Recall and the
  replay), Sentence challenge, Scenario, Progress, and the author tools Record,
  Library and Study (learners never see them; `?mode=author`).

## Deploying

The camera needs a secure context, and the app is a static build with no
backend.

**Standalone (team repository).** Deploy from the CLI, not by importing the
repo: Vercel's import flow only lists repositories the Vercel account owns, and
this module lives in a repo owned by a teammate.

```bash
cd learn-ssl-module/web
npx vercel@latest login
npx vercel@latest --prod
```

Answer `./` for the code directory and decline the offer to customise build
settings; `vercel.json` sets them. The upload honours `.gitignore`, so
`public/wasm` is regenerated by the postinstall hook.

**Suvana.** The Suvana repository deploys this folder as the `suvana-learn`
Vercel project; the Shell at `suvana.help` forwards `/learn/` to it.

**Caching.** `vercel.json` cannot carry comments, so the reasoning lives here.
`models`, `references` and `wasm` are cached for one day with seven days of
background revalidation (not `immutable`), and their URLs carry
`ASSET_VERSION` from `src/app/assetVersion.ts`. **Bump `ASSET_VERSION`
whenever any reference JSON or index, WASM runtime or model file changes**,
including MediaPipe upgrades that copy different WASM files, and port the same
version with the assets. Immutable caching was dropped because a corrected
reference could never reach a browser that had stored the old one.

What a learner downloads (Suvana build, measured 18 Oct 2026 from
`npm run build` and gzip of `public/reference-index.json`):

| When | What |
|---|---|
| First paint | 155.2 kB gzip main script + 25.3 kB gzip styles, plus the **24.3 kB gzip reference index** |
| Choosing a sign | that one recording's frames (tens of kB), cached after |
| First **Start camera** | ~11 MB WASM runtime + 7.8 MB hand model, cached |

The heavy tracking assets are deferred until the camera is actually started,
and are a one-off per device. The agents' gate rule keeps the main script at or
under 160 kB gzip (checked by hand at each merge; no CI step enforces it).

#### The reference index and its budget

The index, which every learner fetches on first paint, is budgeted at
**≤50 bytes gzip per reference**, enforced by `referenceIndex.test.ts` on
every `npm test`.

| | raw | gzip | per reference |
|---|---|---|---|
| 362 references, before | 219 kB | ~23 kB | 63.5 B |
| 501 references, unchanged format | 303 kB | 32.3 kB | 64.6 B |
| 501 references, compact format | 133 kB | 22.3 kB | 44.5 B |
| 520 references, **now** (18 Oct, incl. 19 sentence clips) | **164 kB** | **24.3 kB** | **46.8 B** |

Two changes got it there. Provenance fields that are constant within a corpus
(`attribution`, `licence`, `sourceDataset`, `note`, `signer`) moved into a
`sources` table carried once; and `sourceFile`, `sourceLabel` and `variant` were
dropped from the projection, having no consumer in `src/`. They remain in the
reference files on disk: the index is a projection, not an archive.

**Where the remaining cost sits.** `id` is over half of it. These are UUIDs, so
the cost is entropy that no compression removes. Deriving ids from filenames
was rejected: `referenceId` is written into the attempt log from the loaded
reference file and exported, so it joins an attempt to the reference it was
scored against, and letting the index disagree with the file would break that
join silently.

That is also why the budget is per reference rather than a flat total: a flat
figure cannot separate "the index got fatter" from "there are more signs".

> If that test ever fails, attribute the cost before touching the number:
> gzip the index with each field removed in turn and see which one grew.

| Column | Used for |

### Team workflow: recording your own

Only needed for glosses neither corpus covers. Of the seven glosses the
Introductions scenario needs, YOU, WHERE and CAN ship; **ME, NAME, WHAT and YOUR
are not in either corpus**. `ME` is a special case: the corpus holds `I`, and
whether that is the same SSL sign is a question for the School for the Deaf,
not a rename to apply.

For a usable reference: fill the frame from roughly the waist up, keep both
hands inside it for the whole sign, use even front lighting and a plain
background, and perform the sign once at a natural pace. The review screen
reports hand-tracking coverage; re-record anything below ~90%.

1. Open **Record** (author mode), enter your name, pick a gloss.
2. Record → review the replay → **Save to library**.
3. In **Library**, **Export all for repo** downloads every recording plus a
   `manifest.json`.
4. Move those files into `public/references/`, bump `ASSET_VERSION`, and commit.

Recordings store only landmark coordinates, never video. Until step 3–4 they
live only in your own browser's IndexedDB.

## Sign scoring (DTW)

`src/scoring/` compares a practice attempt to a reference recording:

- `normalize.ts` — per-frame **handshape** features (21 landmarks, wrist-relative,
  scaled by hand size) and **trajectory** features (the wrist path, centred and
  scaled), with aspect-ratio correction. A reference counts as two-handed only if
  two hands are tracked in at least 20% of its frames
  (`TWO_HAND_FRAME_THRESHOLD`); otherwise only its most-tracked hand is scored,
  so a stray hand label does not demand a second hand (L-30).
- `dtw.ts` — dynamic time warping, so attempts signed faster or slower still
  align.
- `score.ts` — `scoreAttempt(attempt, reference)` → 0–100 score, per-hand
  breakdown, per-landmark deviation along the alignment, the alignment itself
  (for the replay) and typed tips.

**Handedness.** Every attempt is scored as performed and mirrored, and the
better result wins (`result.mirrored`). A left-dominant learner performing a
right-handed reference is signing correctly.

**Tips** (`hints.ts`), at most two, from measured quantities only: missing hand
or no hands tracked; *hand path* when the trajectory term outweighs the
handshape term; *timing* when the active duration is below 0.67× or above 1.5×
the reference's (untuned); otherwise a close-match message at 85+ or "watch the
replay". Learner wording is kvn's short, everyday English.

### Finger labels (L-33)

One cut-off for every sign failed twice (D-A15): with the draft's 0.1, 99.7% of
fingers in correct takes exceeded it; a cut-off at the 95th percentile of
same-sign worst-joint deviation flagged only 17.2% of different-sign fingers
(L-30 handoff). L-33 then ran one test of **per-sign, per-finger cut-offs**
with rules and a pass bar fixed before any result (D-A31): *Almost* above the
sign's same-sign 90th percentile, *Wrong* above its 98th, nearest rank, strict
`>`; only signs with at least 8 takes (23 of the 33 calibration signs); four
folds, held-out takes never used to fit their own cut-offs.

Held-out results on one fluent signer's recordings (never learner accuracy):
false *Wrong* on **13.24%** of correct attempts (67/506; bar ≤20%);
**70.65%** of *clearly different* fingers labelled *Wrong* (8,021/11,353; bar
≥50%), where "clearly different" is a subset chosen from training takes only,
so it must not be quoted as the all-fingers rate, which is **40.32%**
(29,395/72,900). The pass is an aggregate: per-sign false-*Wrong* rates range
from about 5% to 4 of 8 attempts, and only 12 of 23 signs are individually at or
under 20%. The L-17 (14.5%) and L-30 (17.2%) figures used a different protocol,
so 40.32% is not an improvement estimate. The shipped table
(`src/scoring/fingerCutoffs.ts`, generated by `fingerCutoffs.generate.test.ts`,
with corpus and scorer hashes) is a full-data refit and has no separate
held-out measurement.

Labels appear only for references whose frames match the fitted reference: 22
signs in the default selection (JANUARY qualifies, but its default reference is
the Kaggle recording, which has no fit). A finger can read *Wrong* beside a
*Great match*. Details and reproduction: `docs/plan/handoffs/L-33.md` in the
Suvana repository.

### Score-scale calibration

The distance→score anchors are **fitted to measured data**. The corpus records
many takes of each sign by one fluent signer, which labels itself: two takes of
one sign are a correct rendition performed twice; takes of different signs are a
wrong-sign attempt. `src/scoring/calibration.test.ts` measures both
distributions over 557 takes of 32 signs (33 on disk; one has a single take).

Distance distributions when the anchors were fitted (earlier scorer, before
L-30; [`calibration-report.md`](calibration-report.md)):

| pair | p10 | median | p90 |
|---|---|---|---|
| same sign, another take | 0.222 | **0.459** | 0.767 |
| a different sign | 0.405 | 0.662 | 0.954 |

`D_PERFECT` / `D_ZERO` are the correct-rendition p10 / p90 (0.22 / 0.77), so
the best tenth of correct renditions score 100 and the worst tenth score 0.
The previous values (0.05 / 0.35) put `D_ZERO` below the median correct
rendition, so a genuinely correct attempt scored zero.

> **This grades; it does not classify.** The current scorer (after L-30)
> separates two takes of the same sign from two different signs at **75.7%**
> at the best threshold, against a **65.4% majority-class baseline**, on 1,516
> pairs (524 same-sign, 992 different-sign) from one fluent signer; ROC AUC on
> the same pairs is **0.758** (D-A35). The draft thesis's 74.6% and ROC AUC
> 0.744 came from the earlier scorer and were reproduced exactly before the
> current one was measured (`docs/plan/handoffs/auc-remeasure.md`). Never call
> this accuracy or learner performance, never quote one figure without the
> 65.4% baseline, and do not present the difference as an improvement. Some
> distinct signs are closer together than two takes of one sign typically are,
> so a high score means *this target sign was performed well*, not *this was the
> right sign*. Appropriateness (`rubric.ts`) therefore compares only within a
> scenario's small vocabulary. `src/scoring/anchors.probe.test.ts` reports the
> closest confusable pairs.

> **Still provisional:** every calibration take is by one fluent signer, so
> this captures the natural variation of a *correct* rendition, not a learner's
> wider spread. The anchors and the 60/85 bands were also set before the capture
> change of L-07 (longer window, trimming) and were not recalibrated. Re-fit
> against real learner attempts graded by an SSL teacher before quoting
> anything against the proposal's ≥90% target.

### Fitted feature weights, and three rejected changes

`W_SHAPE` / `W_TRAJ` were fitted by grid search over the same corpus
(`src/scoring/weights.fit.test.ts` →
[`weight-fit-report.md`](weight-fit-report.md)): **0.8 / 0.2** rather than the
assumed 0.7 / 0.3. The separations below were measured with the earlier scorer
during that fit and are kept as the record of the decision.

Separation rose monotonically with `W_SHAPE`, peaking at 78.6% when movement is
discarded entirely. That maximum was deliberately not taken: the search
optimises *"is this the same sign?"*, while this scorer *grades a known sign*,
and a scorer blind to movement would award full marks for the right handshape
with the wrong movement.

| Change | Effect | Verdict |
|---|---|---|
| Sequence-stable instead of per-frame hand-size scaling | 73.7% → 73.4% | No effect; reverted |
| Trajectory as frame-to-frame **velocity** | 73.5% → 75.5% separation | **Reverted despite winning**: a learner moving in entirely the wrong direction still scored 100, caught by `score.test.ts` |
| `W_SHAPE` = 1.0 (drop movement) | 78.6%, the maximum | Rejected on the same grounds |

## Learner model and game

Rule-based by design; no learned model, correctness judgement or learning gain
is claimed. `mastery.ts` keeps an EWMA of match scores (alpha 0.5; *improving*
≥ 0.6; *mastered* ≥ 0.85 after ≥ 3 attempts) and a practice need
`0.75 × (1 − mastery) + 0.25 × min(days / 5, 1)`; a sign with need above 0.5 is
due. `session.ts` builds unit sessions (up to 8 signs, 2 reviews then 1 new),
`nextExercise.ts` suggests the next stage and speed for one sign, and `game.ts`
holds stars, unit states, the daily goal, streak and XP. All constants are
untuned heuristics or kvn's approved product rules. Rules, reasons and edge
cases: [`src/learner/ADAPTATION.md`](src/learner/ADAPTATION.md).

## Scenarios

`src/scenario/` + `src/data/scenarios/` run a scripted conversation where each
turn asks for **one** sign, scored through the same DTW path. Two of the five
proposal scenarios ship (no third, DN-19):

| Scenario | Turns | References |
|---|---|---|
| **Restaurant** | 5 (KANAWA, BONAWA, 500, MILADII GANNAWA, BILPATHA) | All from real signers (Kaggle corpus). Demo this one. |
| **Social Gathering (Introductions)** | 7 (ME, YOU, NAME, WHAT, WHERE, CAN, YOUR) | **Preview: 3 of 7 playable** (YOU, WHERE, CAN, Yohan corpus). The other turns show *reference pending* and are skipped. Aligned with the speech-to-sign component's avatar glosses. |

- **Guided or Recall.** Guided shows the reference before the attempt; Recall
  shows the sign only after the turn.
- **Hints are author-only.** The coaching hints in the scenario files describe
  movements no signer has validated, so only author mode shows them, and
  "that looked closer to another sign" is no longer shown to learners.
- **Verified end to end** (Restaurant, references as attempts): the requested
  sign scores 100; a different sign from the same scenario scores 33 or below
  with appropriateness 0, including KANAWA/BONAWA.
- **Data-driven.** A scenario is a JSON file; adding one means authoring JSON
  and listing it in `src/data/scenarios/index.ts`.
- **No silo.** Every turn logs to the same attempt log as Practice; the logged
  score is the DTW match score, not the rubric total.

> The conversational order in `introductions.json` is a **draft pending
> validation by an SSL teacher** (School for the Deaf, Ratmalana). Each turn
> asks for a single gloss; the surrounding text is English context, never a
> claim about SSL word order.

### Rubric — what is measured, and one honest deviation

The proposal scores each turn on accuracy 40%, appropriateness 30%,
fluency-timing 20% and non-manual markers 10%, without defining how to compute
them, so the definitions below are ours.

**Deviation: non-manual markers are not scored.** Facial expression, head tilt
and body movement are meaningful in SSL, but this build tracks hand landmarks
only, so any number for them would be fabricated. Their 10% goes to the first
component, giving **50 / 30 / 20**, and the scenario summary says so.

| Component | Weight | Operational definition | Known limitation |
|---|---|---|---|
| **Match** (the proposal's "accuracy") | 50% | DTW match score of the attempt against the requested sign's reference, 0–100, on the calibrated scale above. | One signer's reference; a match, not a correctness judgement. |
| **Appropriateness** | 30% | Did the learner produce the requested sign rather than another sign **in the scenario's vocabulary**? `50 + 50 × (target − best other) / 15`, limited to 0–100; a tie scores 50. | Closed-set: it cannot detect a sign outside the scenario's vocabulary. |
| **Fluency & timing** | 20% | Attempt duration over reference duration, symmetric in log space; full marks within ±25%, zero at 2.5× too fast or too slow. | Whole-clip pace only. |

**Unmeasurable ≠ zero.** A component with no data (appropriateness in a
one-sign vocabulary, fluency with no duration) reports **n/a** and its weight is
redistributed.

## Feedback latency — proposal target ≤300 ms

### Operational definition

The clock starts at the **capture of the final frame of the attempt** and stops
when the **feedback has been painted**:

| Stage | What it covers |
|---|---|
| **Hand tracking** | MediaPipe inference on that final frame, the overlay draw and the hand-off to scoring |
| **Sign scoring** | DTW against the reference; in a scenario turn, also the appropriateness pass over the scenario vocabulary |
| **Showing feedback** | React's commit plus the browser's paint |

**Excluded, because JavaScript cannot observe them:** the camera's own delay
before the frame reaches the page, and the display's response time. Every
figure is a *software pipeline* latency, not glass-to-glass.

The measurement **errs high**, which is the safe direction for an "under
300 ms" claim: the take ends on whichever frame arrived last, and the paint
mark is taken at the frame boundary after the paint.
`src/metrics/useFeedbackLatency.ts` explains why a layout effect and two nested
`requestAnimationFrame`s are both needed. Samples taken while the tab is in the
background are discarded.

### Where the numbers appear

- **Progress tab** — median, 95th percentile, share within 300 ms and the stage
  breakdown from that browser's own attempts; *provisional* below 20 samples.
- **Study export** — summary plus every sample; **blank, never 0**, where no
  sample was taken.
- **End-to-end measurement for the thesis** — Q-09 (n = 20, one laptop); not
  run yet. Until it is, do not claim the ≤300 ms target is met.

### What can be measured without a camera

`src/metrics/scoring.bench.test.ts` times the **scoring stage** against the real
reference corpus and regenerates [`latency-report.md`](latency-report.md).
Quote it as *scoring cost*, never as feedback latency. Its figures are medians
of repeated runs after a warm-up. **Open:** the bench still builds its stand-in
take as `reference duration + 1500 ms`, the capture window before L-07; the
shipped window is `max(2 × duration, duration + 3000 ms)`, so the bench's
attempts are shorter than real ones and its cost figures are likely low.
